# 英国Skyway低空高速公路（格言低空译，2024）

> 源文件：`原始素材/文章/低空高速公路｜英国Skyway项目的总体介绍.md`
> 译者：格言
> 来源：低空产研记录（微信公众号），2024-10-08
> 原文事件：2022.07.18 范堡罗航展，MP Kwasi Kwarteng 宣布 Skyway 项目

## 核心定位

英国Skyway项目是**全球首个大规模地面传感器驱动无人机专用高速公路网络**。由Altitude Angel牵头、BT/EE提供蜂窝连接、Skyports负责BVLOS验证——265km连接英格兰南部/东南部6+2城市，以"感知外置"（地面传感器）+"通信公用"（4G/5G）+"避撞集中化"（ARROW→UTM）三重技术特征，开创了不同于日本（机载CNS）和美国（UTM协调）的**第三种低空走廊技术范式**。

## 五大板块

### 一、项目概况

| 要素 | 详情 |
|:---|:---|
| **宣布时间** | ★ 2022.07.18 范堡罗航展 |
| **宣布人** | MP Kwasi Kwarteng（商业/能源/产业战略大臣） |
| **走廊长度** | **265 km**（165英里）——世界最长无人机高速公路 |
| **一期城市** | Reading, Oxford, Milton Keynes, Cambridge, Coventry, Rugby（6城） |
| **延伸城市** | Southampton（南岸）+ Ipswich（东岸） |
| **资金来源** | BEIS / Innovate UK——航空航天£2.73亿投资计划→£1.055亿综合航空系统专项 |

### 二、ARROW 技术架构

| 层 | 组件 | 功能 | 提供商 |
|:---|:---|:---|:---|
| **感知** | 地面传感器网络（沿公路部署） | 持续监控低空→实时位置视图 | Altitude Angel（专利） |
| **通信** | 4G+5G蜂窝 | 连接传感器↔服务器↔无人机 | BT / EE |
| **分析** | UTM交通管理系统 | 飞行引导+战术防撞指令 | Altitude Angel |
| **执行** | 机载DAA | 接收+执行ARROW指令 | Altitude Angel（2020开发） |
| **监督** | 指挥中心 | 初期人工监督→逐步自动 | 经培训操作员 |

### 三、合作伙伴生态

| 伙伴 | 角色 | 关键贡献 |
|:---|:---|:---|
| **Altitude Angel** | ★ 牵头方 | ARROW专利技术+UTM系统 |
| **BT Group / EE** | 通信网络 | 英国最大最可靠4G/5G网络；£500万投资Altitude Angel |
| **Skyports** | BVLOS运营验证 | 数千小时BVLOS飞行经验→试飞验证可行性 |
| **CAA** | 监管审查 | 渐进式——试飞→数据→审查→安全协议整合 |
| **Reading等地方当局** | 地方政府支持 | 空域协调+地面配套 |

### 四、应用场景

| 场景 | 特征 |
|:---|:---|
| **应急响应** | 高优先级、低延迟、突发性 |
| **搜索与救援** | 广域覆盖、持久续航 |
| **医疗运输** | 器官/血液/药品——时效敏感、高可靠性 |
| **偏远地区配送** | 苏格兰等——邮件+药品定期配送 |
| **基础设施巡检** | 桥梁/铁路/电力——重复航线 |
| **农业调查** | 季节性、大面积 |

### 五、时间线

| 节点 | 事件 |

## 四种走廊范式对比

| 范式 | 代表 | 感知主体 | 通信网络 | 主要对象 | 避撞决策 |
|:---|:---|:---|:---|:---|:---|
| **①低空高速公路** | ★ 英国Skyway | 地面传感器 | 4G/5G蜂窝 | 无人机 | 集中式（ARROW） |
| **②AAM走廊** | 日本 | 机载CNS | 多链路专用 | eVTOL | ANSP→机体自主 |
| **③管道** | 美国NASA/FAA | 机载+UTM | ADS-B | eVTOL+无人机 | UTM协调 |
| **④分层走廊** | GCC | 机载+ADS-B | ADS-B+增强 | eVTOL+无人机 | 飞行规则约束 |

## 与子课题3 关联

| 维度 | 关联点 |
|:---|:---|
| **线性走廊一维容量** | $C_{linear}=v_{uniform}/s_{min}\times n_{lanes}\times\eta_{network}$——最简走廊容量模型，与日本二维$C_{corridor}$互补 |
| **感知架构→$s_{min}$差异** | 地面传感器精度→$s_{min}$ vs 机载CNS精度→$s_{min}$——同一走廊不同架构→不同容量上限 |
| **公用网络可靠性** | $\eta_{network}$波动→容量非恒定→需动态网络监控→实时容量调整 |
| **走廊范式谱系完整** | 四种走廊模型（地面感知/机载CNS/UTM协调/规则分层）→子课题3可选择/融合建模 |
