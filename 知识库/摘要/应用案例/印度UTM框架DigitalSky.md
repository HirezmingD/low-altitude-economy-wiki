# 印度多供应商UTM框架：DigitalSky（Aviation Jeta，2026）

> 源文件：`原始素材/文章/Singapore's UTM Push Draws Attention to India's Drone Traffic Framework.md`
> 来源：Aviation Jeta，2026-05-30
> 背景：新加坡Thales UTM合同签署→引发对印度UTM框架的关注

## 核心定位

全球UTM治理的**第四种范式**——多供应商分布式。DigitalSky（DGCA中央监管与数据交换平台）+ 多个公私UTM服务提供商通过互操作标准并行运行。Very Low Level空域（地面至1000ft AGL）定义为UTM空域。与新加坡（集中统一）、挪威（全国一体化）、欧盟U-space（法规驱动）构成四种UTM治理模式的完整谱系。

## 四系统UTM对标

| 范式 | 代表 | 架构 | 核心特征 |
|:---|:---|:---|:---|
| **★ 分布式** | 印度 | DigitalSky+多供应商 | 公私竞争+互操作同步 |
| **统一式** | 新加坡 | Thales AstraUTM | 全国单一平台一站式 |
| **一体式** | 挪威 | Avinor+CIS+USSP | 全国ANSP主导+U-space |
| **法规式** | 欧盟 | BURDI参考设计 | EU法规→各国实施 |

## 印度框架核心要素

| 要素 | 详情 |
|:---|:---|
| **中央平台** | ★ DigitalSky——注册+许可+空域信息+利益相关方整合 |
| **空域定义** | Very Low Level——地面至**1000ft** AGL |
| **供应商** | 多个公私UTM服务提供商——通过互操作标准同步 |
| **实施** | 分阶段——试验→整合演练→渐进规模化 |
| **监管** | DGCA（印度民航总局） |

## 核心挑战

| 挑战 | 内容 |
|:---|:---|
| **交通可见性** | 多供应商→全局态势的完整可见性 |
| **跨供应商移交** | UA跨区域→移交协议+责任划分 |
| **临时限制同步** | 实时同步至所有供应商 |
| **航线冲突** | 共享走廊→多供应商航线交叉 |
| **地理围栏一致性** | 所有供应商同步更新 |
| **1000ft垂直界面** | UTM↔ATM垂直协调 |

## 子课题3 关联

| 维度 | 关联点 |
|:---|:---|
| **多供应商→容量折减** | $C_{multi}<C_{single}$——$\eta_{coordination}<1$ |
| **互操作标准→协调成本** | 标准化程度→$\eta_{coordination}$大小 |
| **1000ft界面→垂直耦合** | UTM-ATM垂直边界→容量交互约束 |
