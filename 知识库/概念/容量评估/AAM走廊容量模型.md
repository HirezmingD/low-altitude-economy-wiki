# AAM走廊容量模型

> 基于日本ConOps第4章的AAM走廊概念，将走廊定义为**独立、封闭、可控的容量计算单元**——仅限CNS性能达标航空器进入，统一方向/速度，内部DCB+ADS-B合规监控。与NASA/FAA管道范式、GCC分层走廊、英国Skyway低空高速公路形成**四种走廊模型的完整对照**。

## 一、日本AAM走廊定义

### 1.1 核心特征

| 特征 | 说明 | 容量含义 |
|:---|:---|:---|
| **性能准入** | 仅限满足航空器性能要求的航班进入 | CNS门槛→低性能拒入→容量保护 |
| **高密度运行** | 统一飞行方向与速度 | 消除航向冲突→最小间隔可压缩 |
| **走廊内DCB** | 飞行计划需经批准 | 需求侧主动控制→防过载 |
| **ADS-B合规监控** | 持续监控走廊内合规性 | 实时偏离检测→安全间隔保障 |
| **动态激活** | 按需激活/解除（动态空域管理） | 容量非固定值→随需求弹性调整 |

### 1.2 走廊在空域结构演进中的位置

```
阶段1（2020s后）：现有空域 + AAM航路 ──→ 无走廊
阶段2（2030s）：  + AAM走廊 + 动态空域管理 ──→ ★走廊引入
阶段3（2040s+）： + 自主间隔保持空域 + 走廊内自主间隔保持 ──→ 走廊升级
```

## 二、走廊容量公式

### 2.1 基本参数化

$$C_{corridor} = f(L, s_{min}, v_{uniform}, CNS_{threshold}, n_{lanes})$$

| 参数 | 定义 | 日本ConOps来源 |
|:---|:---|:---|
| $L$ | 走廊长度 | 航线设定 |
| $s_{min}$ | 最小间隔距离 | CNS性能门槛→最小间隔/机载传感器精度 |
| $v_{uniform}$ | 统一巡航速度 | 走廊内统一速度→消除速度差冲突 |
| $CNS_{threshold}$ | 准入性能门槛 | 仅限性能达标航空器→低于门槛拒入 |
| $n_{lanes}$ | 车道数 | 单向/双向/多层 |

### 2.2 容量上限推导

基于日本ConOps描述，走廊容量受以下因素制约：

1. **CNS性能门槛**：$C_{corridor} \propto \frac{1}{s_{min}}$，其中$s_{min} = f(CNS_{performance})$——性能越高→间隔越小→容量越高
2. **统一速度**：$C_{corridor} \propto v_{uniform}$——统一高速→单位时间通过量高
3. **DCB约束**：飞行计划审批制→需求不得超过DCB计算的可用容量
4. **动态调整**：按需激活→峰值容量可临时提升（通过激活更多走廊或增加走廊密度）

### 2.3 与管道范式的比较

| 维度 | 日本AAM走廊 | NASA/FAA管道范式 | GCC分层走廊 | ★ 英国Skyway低空高速公路 |
|:---|:---|:---|:---|:---|
| **准入条件** | ★CNS性能门槛（硬性） | 特定规则+程序+性能标准 | 飞行规则+空域分类 | ★ 走廊注册+CAA许可 |
| **间隔保持** | 阶段2=ANSP→阶段2后期=机体自主 | UTM协调 | VFR/IFR→自主 | ★ ARROW地面系统集中→无人机执行 |
| **密度控制** | ★走廊内DCB+飞行计划审批 | 走廊准入控制 | 分层+用例优先级 | ★ UTM统一管理+初期人工监督 |
| **动态性** | ★动态空域管理（按需激活/解除） | 相对静态 | 分阶段演进 | 走廊固定路线+传感器线性扩展 |
| **合规监控** | ADS-B持续监控 | ADS-B In/Out | ADS-B+增强监视 | ★ 地面传感器+蜂窝实时 |
| **自主化路径** | 走廊内先行验证自主间隔保持 | TCL/UML渐进 | VFR→IFR→自主 | ★ 集中决策→逐步自动化（非每机自主） |
| **感知主体** | 机载CNS设备 | 机载+UTM | 机载+ADS-B | ★ 地面传感器网络（感知外置） |
| **通信骨干** | 多链路专用（卫星+地面+机载） | ADS-B链路 | ADS-B+增强 | ★ 公用4G/5G蜂窝 |
| **主要对象** | eVTOL（载人+货运） | eVTOL+无人机 | eVTOL+无人机 | ★ 无人机（BVLOS货运/物流/应急）—非载人 |
| **走廊拓扑** | 点对点航线 | 管道（tube） | 分层（高度层） | ★ 线性（沿公路带状） |

## 三、CNS性能门槛→容量保护

### 3.1 机制

```
航空器CNS性能评估
    │
    ├── 达标 → 准入走廊 → 高密度运行
    │
    └── 不达标 → 拒入走廊 → 仅限走廊外运行（低密度/传统空域）
```

### 3.2 容量保护逻辑

- 走廊内所有航空器满足统一CNS性能标准→间隔可压缩至该标准的最小安全值
- 不达标航空器无法进入→走廊内不会出现"最弱环节决定整体安全"的情况
- 容量保护是**供给端**的保护——不是限制需求，而是确保供给质量

### 3.3 对子课题3的映射

中国GeoSOT网格化空域中，可将每个网格单元视为"微走廊"：
- 网格CNS性能等级→该网格的最小安全间隔
- 不达标航空器→限制进入高等级网格→降级至低等级网格
- 红-黄-绿三级可直接映射为CNS门槛的三档

## 四、走廊→自主间隔保持→容量阶跃

### 4.1 范式转换

| 阶段 | 间隔保持主体 | 最小间隔约束 | 容量特征 |
|:---|:---|:---|:---|
| 阶段1 | ANSP/驾驶员 | 人的认知能力（秒级反应） | 线性约束 |
| 阶段2走廊内 | 机体自主（先行验证） | 传感器精度+算法响应（毫秒级） | 容量大幅提升 |
| 阶段3自主间隔保持空域 | 机体自主（普及） | 机载传感器+AI决策 | ★阶跃增长 |

### 4.2 容量阶跃的建模

$$C_{autonomous} = C_{manual} \times k_{autonomy}$$

其中$k_{autonomy} > 1$，具体值取决于：
- 机载传感器精度（决定了自主间隔保持的最小安全距离）
- 通信延迟（决定了协同避撞的响应时间）
- 算法可靠性（决定了可接受的风险水平）

## 五、子课题3建模启示

1. **走廊=独立容量单元**：每个走廊可独立计算容量→多个走廊+自由空域=总空域容量
2. **CNS门槛→网格准入**：GeoSOT网格可借鉴走廊的"CNS性能分级准入"机制
3. **动态走廊→弹性容量**：按需激活/解除→容量不是固定值而是需求函数
4. **自主间隔→容量阶跃**：技术跃迁导致容量非线性增长→模型需包含"技术代际"变量
5. **ADS-B合规→实时容量监控**：走廊内持续合规监控→实时饱和度计算的传感器基础
