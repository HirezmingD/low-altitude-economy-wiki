# 低空空域结构设计范式

## 定义

**低空空域结构设计范式**是指在 LAAM 框架下组织和管理低空空域空间布局的基本架构方案。由于传统 ATM 的扇区划分方法无法线性扩展至低空环境（不可扩展、成本极高），学术界提出了四类基本设计范式。截至 2025 年，**尚未有任何一种范式实现标准化或达成共识**。

## 四类空域结构范式

### 范式对比

| 范式 | 基本特征 | 容量特性 | 冲突风险 | 适用场景 |
|:---|:---|:---|:---|:---|
| **完全混合**（Free Flight） | 无结构化空域，飞行器以最优直飞航线运行 | 理论容量最高（无结构约束） | 高（缺乏预结构化分隔） | 低密度农村空域 |
| **分层**（Layered/Stacked） | 空域垂直堆叠，每层专用于一种飞行器类型和航向 | 每层容量可控，总容量=Σ层容量 | 层内需间隔保证，层间天然分隔 | 城市环境（最受关注） |
| **分区**（Zonal） | 按风险暴露水平或服务等级划分区域 | 高风险区容量低、低风险区容量高 | 区域内需管理，区域边界需协调 | 混合环境 |
| **管道/走廊**（Tubular/Corridor） | 固定飞行走廊，统一速度限制，安全间隔内维护 | 走廊容量=速度/间隔×车道数 | 低（预结构化分隔） | 高密度固定航线 |

### 各范式的详细特征

#### 完全混合

```
起点 ────────────→ 终点（直飞，最短路程）
      自由选择高度和速度（优化燃油/成本）
      ← 冲突靠自主感知与避让（SACA）解决 →
```

- 优点：最大灵活性、最小基础设施
- 缺点：缺乏可预测性、冲突解决完全依赖机载系统
- 容量建模：基于风险的方法（安全区圆盘 + 三维网格 + Bron-Kerbosch 团计算）

#### 分层（天空车道概念）

```
层 3： 东向交通    ═══════════════
层 2： 西向交通    ───────────────
层 1： 垂直起降     ·  ·  ·  ·  ·
```

- **天空车道**（Sky-lane）：每层进一步划分为条状矩形空间（限制高度和宽度）
- 车道交汇处采用类似道路交通信号的**时基优先级控制**
- 环形交叉路口概念（替代时基分隔）
- 大都市项目（Metropolis）的容量估计：容量 = f(L, CR_max, k, f(α))

#### 分区

| 分区标准 | 区域类型 | 容量含义 |
|:---|:---|:---|
| 按风险暴露 | 农村 → 人口密集 → 城市 → 人员集会 | 风险越高，间隔越大，容量越低 |
| 按 CNS 性能 | 高精度区 → 中精度区 → 低精度区 | 性能越高，间隔越小，容量越高 |
| 按服务等级 | 战术指令型（Zu）→ 建议型（Zz）→ 无服务型（X） | 服务等级越高，可支持的密度越高 |

#### 管道/走廊（NASA/FAA UAM 走廊方案 + ★日本AAM走廊）

**NASA/FAA方案**：
```
══════════════════════════════════
  UAM走廊（专用规则、性能标准）
  - 容纳 eVTOL、直升机、固定翼
  - 空域类别不影响运行
══════════════════════════════════
```

- NASA/FAA 提议的 UAM 走廊：特定规则、程序和性能标准适用于所有飞机
- 走廊内由 UTM 协调的车辆在走廊上空运行
- 适用于高密度城市空中交通

**★日本AAM走廊**（阶段2标志性概念，ConOps第4章）：

| 特征 | 内容 | 与NASA/FAA差异 |
|:---|:---|:---|
| **准入控制** | ★CNS性能门槛——仅限达标航空器 | NASA/FAA依靠规则+程序，非硬性性能门槛 |
| **DCB集成** | ★走廊内DCB（飞行计划审批制）+ 与垂直起降场DCB联动 | NASA/FAA垂直机场DCB相对独立 |
| **合规监控** | ADS-B持续监控 | 类似 |
| **动态性** | ★按需激活/解除（动态空域管理） | NASA/FAA走廊相对静态 |
| **自主化路径** | 阶段2后期走廊内先行验证**自主间隔保持** | TCL/UML渐进 |
| **间隔主体转移** | ANSP→机体自主（走廊内先行） | UTM协调为主 |

**日本走廊在空域结构演进中的位置**：

```
阶段1：现有空域 + AAM航路 ──→ 无走廊，基于现有ATM概念
阶段2：+ AAM走廊 + 动态空域管理 ──→ ★走廊引入，CNS门槛+DCB
阶段3：+ 自主间隔保持空域 + 动态走廊 ──→ 走廊升级，机体自主间隔+四层空域共存
```

> ★ 详见概念页：[AAM走廊容量模型](/知识库/概念/容量评估/AAM走廊容量模型.md)

**走廊容量公式**：$C_{corridor} = f(L, s_{min}, v_{uniform}, CNS_{threshold})$ ——日本走廊将"准入控制+统一速度+DCB"三重机制叠加，形成独立容量计算单元。

## 与 GeoSOT/北斗网格的定位关系

| 维度 | GeoSOT（中国方案） | 国际四范式 |
|:---|:---|:---|
| 理论基础 | 地球立体网格编码（GB标准） | 空域结构设计理论 |
| 核心单元 | 10m/20m 立方体网格 | 层/区/管道/自由空间 |
| 本质 | **空间编码基础设施**（"how to index"） | **空域组织架构**（"how to organize"） |
| 关系 | GeoSOT 是实现分层/分区范式的**空间编码工具** | 分层/分区是 GeoSOT 可服务的**上层架构方案** |

> GeoSOT 在国际学术谱系中可定位为"分区+分层"范式的**混合实现方案**——北斗网格提供统一编码，红绿灯系统提供分区准入控制，功能分层提供垂直堆叠。

## 与本课题的关联

子课题3 的容量评估模型需要明确定义**以何种空域结构为建模前提**：

1. **若采用分层范式**：容量 = Σ层容量，层内容量取决于间隔标准和交通组合——与子课题3 的网格化容量评估直接兼容
2. **若采用分区范式**：不同风险区的容量基准值不同——与多因素耦合模型的风险维度对齐
3. **若采用管道范式**：走廊容量 = 速度/间隔 × 车道数——适用于固定航线场景
4. GeoSOT 编码体系天然支持上述范式的混合实现
