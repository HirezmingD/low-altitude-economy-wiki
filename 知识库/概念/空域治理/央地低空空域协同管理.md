# 央地低空空域协同管理

## 定义

**央地低空空域协同管理**是指在低空空域管理领域，通过重新配置中央与地方之间的权责关系，构建"**中央统领，地方主导**"的纵向权力架构，同时利用一体化综合监管服务平台实现横向部门协调的管理体制。其核心目标是突破传统"中央统一监管"模式的局限，在保障国家安全的前提下充分发挥地方积极性，适应低空经济**信息化、智能化、规模化**的发展趋势。

> 这是知识库首篇以"央地关系"为分析框架的治理理论概念页。

## 现行体制：军民航分层体系

### 结构

| 体系 | 管理层级 | 对应职责范围 |
|:---|:---|:---|
| **军航** | 空军 → 军区空军 → 军师级航空单位 → 军航机场 | 全国 → 飞行管制区 → 飞行管制分区 → 机场管制区 |
| **民航** | 民航空管局 → 地区空管局 → 空管分局/站 | 区域管制 → 进近管制 → 机场管制 |

### 三大病灶

| 问题 | 表现 | 影响 |
|:---|:---|:---|
| **多头审批** | 空域使用权、起降点核准等分属军航不同单位（航行/作战部门），单个飞行任务需协调**多个管制单位** | 效率低下 |
| **"一刀切"逻辑** | 以传统航空器空域准入规则为蓝本，对所有空域准入普遍视为**特权** | 无人机"合法飞行身份难以获得" |
| **地面-空中执法分离** | 空域管理部门难以单独开展有效地面执法 | "黑飞"响应滞后 |

### 《暂行条例》（2024）的突破与局限

| 突破 | 局限 |
|:---|:---|
| 首次明确县级以上地方政府**属地管理责任** | 难以涵盖/规制各类新型低空活动 |
| 赋予公安机关对"黑飞"**先期处置权**（第41条） | 未完全明确央地职权配置 |
| 首次以行政法规形式为低空空域开放奠定制度基础 | 未打破传统航空监管的**全流程逐一审批**框架 |

## 央地关系重构框架

### "中央统领，地方主导"的权力配置

```
┌─────────────────────────────────────────────────────┐
│                  低空空域管理体制                      │
├───────────────────────┬─────────────────────────────┤
│     中央（统领）        │       地方（主导）            │
├───────────────────────┼─────────────────────────────┤
│ · 战略谋划、组织协调     │ · 细化监管制度（本地空域环境）  │
│ · 许可/空域分配原则制定  │ · 承担低空飞行活动具体管理     │
│ · 标准制定（民航监管部门）│ · 因地制宜促进产业发展         │
│ · 国家安全统一管控       │ · 统筹地面与空中执法          │
└───────────────────────┴─────────────────────────────┘
```

### 可行性三维论证

| 维度 | 论据 |
|:---|:---|
| **法理基础** | 宪法第3条第4款："中央的统一领导下，充分发挥地方的主动性、积极性" |
| **功能优势** | 地方政府可统筹协调地面执法+空中执法；公安机关已积累"黑飞"处置丰富经验 |
| **地方实践** | 深圳2023年率先立法；四川/重庆"区域管理" vs 无锡/深圳"高度管理"——两套模式已验证可行 |

### 必要性双维论证

| 维度 | 论据 |
|:---|:---|
| **风险规制** | 现行规制仅覆盖**实体风险**（坠/撞机），未覆盖**信息风险**（隐私/国家安全）；仅以重量分类无法应对智能化趋势 |
| **产业发展** | 不同地区空域环境差异大（山脉/建筑/军事设施）；商业公司+地方政府合作已成可行模式 |

## "三化"趋势对管理体制的挑战

> ★ 核心洞察：信息化、智能化、规模化三大趋势，系统性地挑战了现行"全流程逐一审批"的监管框架。

| 趋势 | 具体表现 | 对监管的冲击 | 对子课题3 的启示 |
|:---|:---|:---|:---|
| **信息化** | 高分辨率摄像头+热成像 → 环境感知能力 → 数据泄露风险 | 现行规制忽视信息风险；需新增信息安全维度 | 多因素耦合需纳入**信息安全折减因子** |
| **智能化** | AI 深度学习 → 视觉感知+路径规划+自主决策 | **算法替代重量**成为核心风险因素；以重量为唯一分类标准的规制框架失效 | 容量折减因子需从"静态重量"转向**动态算法风险评估** |
| **规模化** | 未来城市同时在空**百万级**UAV；起降次数更高 | "全流程逐一审批"无法支撑高密度场景 | ★ 直接论证子课题3 **自动化容量评估**的制度必要性 |

## 渐进转移策略

> 按技术成熟度和应用可控性，分阶段将低空管理权下放地方。

| 阶段 | 对象 | 条件 | 理由 |
|:---|:---|:---|:---|
| **先行下放** | 物流无人机 | 运行范围/状态稳定可控、产业规模效应显著、运营主体集中 | 可控性强，风险可评估 |
| **暂不下放** | 载人eVTOL | 应用范围小、经验不成熟、风险未全面评估 | 不具备变革条件 |

> **美国参照**：美国将无人机按公共、民用（商用）和娱乐用途分类管理，可为中国分类下放提供参考。

### G/W 空域管理权下放的操作路径

> ★ 来源：王小霞（2026），引述马剑（北京临空国际技术研究院院长）等专家。

**管理权下放的具体安排**：

| 空域类别 | 高度范围 | 管理主体转变 | 操作模式 |
|:---|:---|:---|:---|
| G 类 | <300m | 军航-民航二元 → **军-民-地三方协同** | 地方政府参与管理 |
| W 类 | <120m（轻小型无人机） | 管理权授权**地方政府** | 报备即可使用的友好空域，有望实现轻小型无人机飞行常态化 |

**"管用分离"原则**（《空域管理条例（征求意见稿）》核心创新）：
- 空域管理权（规划/划设/标准）与空域使用权（飞行/运营）在制度层面分离
- 有效解决空域多头管理的体制性矛盾
- 授权地方政府按责任分工参与低空空域管理——**打破"军航-民航"二元垄断**

**空管地区化管理探索**（不具名业内专家）：
- 推行空管地区化管理模式
- 授权**省级**地方政府相关部门参与低空空域管理
- 充分激活地方管理权责与积极性

### 福州实证："军-地-民"协同的标杆案例

> ★ 来源：姚俊臣（2026），引述酒海燕（中国交通运输协会低空交通与经济专委会秘书长）。

福州市在央地协同框架下的改革实践，是"中央统领，地方主导"在地级市层面的**首个量化落地验证**。

**核心成果**：

| 指标 | 改革前 | 改革后 |
|:---|:---|:---|
| 适飞空域占比 | <11%（集中在偏远郊区） | **~50%** |
| 市中心核心经济区 | 全部管制空域 | 动态释放可用 |
| 管理模式 | "被动管控" | **"主动防控"** |

**"军-地-民"三方协同的具体实现**：
1. 出台四份文件形成 **"3+1"顶层制度设计**
2. 建成"榕智九天"市级低空监管运服平台
3. 率先实现**地方政府与空域主管单位协同管理**低空空域资源释放和飞行计划审批
4. 可计算空域网格为核心技术，逐网格动态释放/回收 1000m 以内空域

> 详见：[福州低空空域改革](/知识库/实体/示范区域/中国/福州低空空域改革.md)

## 横向协调：一体化综合监管服务平台

### 平台架构

| 要素 | 内容 |
|:---|:---|
| **法律依据** | 《暂行条例》第23条——国家空中交通管理领导机构统筹建设 |
| **数据来源** | 民航、公安、工信、市场监管等部门**分工采集**：生产、登记、使用信息 |
| **核心角色** | **数据监控载体**（非决策者——不享有"决策"权力，避免与地方执法权重叠） |
| **执法主体** | 地方政府——从平台收集信息 → 实地核实调查 → 行使执法权 |

### 三大核心功能

| 功能 | 实现路径 | 与子课题3 的关联 |
|:---|:---|:---|
| **空域态势预测** | 整合飞行数据（轨迹/高度/类型/注册）+ 外部因素（气象/空域限制/飞行计划）→ **算法模型描述并预测低空空域态势** | ★ 子课题3 ST-GNN 态势预测的直接运行载体 |
| **异常识别与警报** | 实时监控+数据分析 → 识别异常飞行行为 → 发出警报制止 | ★ 子课题3 饱和度监测预警系统的工程实现 |
| **数据基础** | 汇集各部门履职数据 → 形成统一监管数据池 → 为低空交通规则构建提供科学依据 | 容量评估的大数据基础设施 |

### 当前瓶颈

- **数据孤岛**：无人机实名登记系统尚未与公安系统联网
- **数字化水平低**：分布零散、来源多元、领域细化

## 在子课题3 中的定位

| 维度 | 含义 |
|:---|:---|
| **制度定位** | 容量评估的央地分工：中央制定**评估标准与模型框架**，地方输入**本地差异化参数**（地形/军事设施/经济需求） |
| **平台载体** | 一体化综合监管服务平台是容量监测预警系统的**天然运行载体** |
| **需求论证** | "三化"趋势（尤其规模化→百万级同时在线）为自动化容量评估提供**强烈的制度需求** |
| **风险框架** | 风险规制从"重量一维分类"→"重量+算法+信息风险多维分类"→ 容量评估的多因素耦合需扩展维度 |
