# BURDI项目：U空域参考设计实施（2022-2025）

> ★ 欧洲首个**跨境U空域参考设计实施**项目——比利时-荷兰联合，将EU 2021/664法规从理论框架转化为可运营、可推广的"参考设计"。€990万预算/18核心伙伴/3年/三大核心区域（布鲁塞尔+安特卫普+列日）。核心成果：U空域ConOps获批、首个跨境U空域互操作参考设计、BVLOS医疗物流（30min→<13min）+港口巡检实战验证、CISP+USSP+UTM全栈技术整合至TRL 8/9。为整个欧洲U空域部署提供**可复制模板**。

## 核心定位

| 维度 | 定位 |
|:---|:---|
| **全球地位** | ★ 欧洲首个跨境U空域参考设计实施——U-space从理论到实践的里程碑 |
| **核心使命** | 将U-space理论框架转化为可实际运营、可大规模推广的"参考设计" |
| **资金规模** | €990万——EU CEF（连接欧洲设施）计划资助 + SESAR JU支持 |
| **合作规模** | 18个核心合作伙伴 + 4个附属实体——跨部门联盟 |
| **技术成熟度** | ★ 已验证至TRL 8/9——运营就绪阶段 |

## 一、空域条件

| 维度 | 详情 |
|:---|:---|
| **地理范围** | 比利时三大核心区域：**布鲁塞尔**（国际机场+首都）、**安特卫普**（欧洲第二大港+密集城市）、**列日**（货运机场枢纽） |
| **跨境维度** | ★ 比利时↔荷兰——首个跨境U空域互操作验证 |
| **空域复杂度** | 国际机场终端区 + 繁忙港口 + 高密度城市建成区——★ "欧洲最复杂的空域环境之一" |
| **空域类型** | U-space空域（EU 2021/664法规）——与传统ATM系统共存 |
| **首个U-space空域** | ★ 安特卫普-布鲁日港成为首个U-space空域 |

## 二、技术方案

### 2.1 三层技术架构

| 层 | 角色 | 承担方 | 核心功能 |
|:---|:---|:---|:---|
| **CISP**（共同信息服务） | 基础信息提供 | ★ skeyes（比利时ANSP） | 无人机飞行的基本空域+气象信息 |
| **USSP**（U空域服务） | 核心服务提供 | ★ SkeyDrone | 数字飞行授权+交通信息+冲突解脱 |
| **UTM**（无人机交通管理） | 底层平台 | ★ Unifly | U空域服务的底层技术平台 |

### 2.2 U-space 服务谱系（BURDI验证）

| 服务类型 | 服务内容 | 验证状态 |
|:---|:---|:---|
| **基本服务**（EU法规强制） | 网络识别、地理感知、飞行授权、交通信息 | ★ 全部整合验证 |
| **增值服务** | 气象信息、一致性监控 | ★ 额外验证 |

### 2.3 BURDI ConOps（运行概念）

| 维度 | 内容 |
|:---|:---|
| **开发方** | BURDI联盟——依据EU 2021/664法规 |
| **批准方** | CINEA + SESAR JU |
| **覆盖范围** | 空域创建、风险评估程序、利益相关方角色、U空域服务详情——法规未详尽规定的全部环节 |
| **核心贡献** | ★ 为EU法规中"留给成员国决定的实施细节"提供了具体解决方案 |

### 2.4 渐进式三阶段结构

| 阶段 | 内容 | 规模 |
|:---|:---|:---|
| **第一阶段** | 小规模技术/系统测试——验证程序和设备 | 实验室+小范围 |
| **第二阶段** | 逐步扩大到更全面的U空域解决方案 | 扩大范围 |
| **第三阶段** | ★ 全面实战验证——BVLOS医疗+港口+跨境 | 三大核心区域全场景 |

## 四、动态约束

| 约束类型 | 详情 | 子课题3 映射 |
|:---|:---|:---|
| **机场终端区共存** | 布鲁塞尔+列日国际机场→U-space与运输航空在终端区共存——最复杂的空域混合场景 | 混合空域容量模型——$C_{U-space}+C_{ATM}$在同一终端区的双重约束 |
| **跨境制度协调** | 比利时↔荷兰→两国监管框架对接→空域规则/责任划分/数据共享 | 跨境制度边界衰减——★首个可量化的欧洲跨境$C_{cross\_border}$实证数据源 |
| **港口-城市-机场三重复合** | 安特卫普——港口作业+城市建成区+机场终端区三重叠加 | 三重复合环境→空域复杂度指数最大——容量折减极端场景 |
| **远程操控延迟** | BVLOS医疗从英国远程操控比利时无人机→跨境通信延迟 | $f_{CNS}$——远程操控$d_{remote}$→通信延迟→最小间隔↑→容量↓ |
| **社会接受度** | UAM城市环境→公众接受度+地方政府协调——BURDI建立多层次治理框架 | $f_{social}$的多层次实现——非技术性约束的制度化解决路径 |

## 五、制度机制

### 5.1 BURDI治理架构

```
EU层面（CEF + SESAR JU）
      │ 资金+战略指导
      ├──→ CINEA（批准ConOps）
      │
国家层面（比利时BCAA + 荷兰CAA）
      │ 监管审批+空域指定
      │
实施层面（BURDI联盟·18+4实体）
      ├── CISP: skeyes（ANSP）
      ├── USSP: SkeyDrone
      ├── UTM: Unifly
      ├── 经济分析: Future Needs（成本模型+市场需求）
      └── 运营验证: 医院/港口/地方政府
```

### 5.2 核心制度产出

| 产出 | 内容 | 制度影响 |
|:---|:---|:---|
| **ConOps获批** | U空域运行概念——空域创建+风险评估+利益相关方角色+服务详情 | ★ 成为未来EU法规更新和EASA标准化的直接依据 |
| **跨境参考设计** | 比利时-荷兰互操作方案——解决无人机跨越成员国边界 | ★ "互操作性和单一数字天空"关键一步 |
| **ARA+CM程序** | 空域风险评估+协调机制——为BCAA提供实操流程 | 自下而上的监管工具——成员国可直接采用 |
| **成本模型** | Future Needs主导——U空域经济可持续性评估 | 市场需求+成本→商业模式可行性 |
| **多层次治理框架** | 公众+地方政府+运营商——社会接受度的制度化 | ★ 解决非技术性政治和公众接受度问题 |

### 5.3 BURDI 在U-space演进中的位置

## 六、子课题3 启示

| 维度 | 启示 |
|:---|:---|
| **U-space→中国UOM对标** | BURDI的CISP+USSP+UTM三层架构→中国UOM（无人驾驶航空器运行管理系统）可借鉴——CISP≈全国统一数据底座/USSP≈区域服务提供商/UTM≈技术平台。容量评估需在UOM架构中嵌入式部署 |
| **ConOps→容量评估运行概念** | BURDI ConOps覆盖空域创建+风险评估+利益相关方角色→为中国低空容量评估的**运行概念（ConOps）**制定提供方法论模板——特别是"法规未详尽规定的实施细节"的填补逻辑 |
| **跨境互操作→跨省容量协调** | 比利时-荷兰跨境U空域→中国跨省低空飞行（如苏州↔上海、杭州↔绍兴）的容量协调——BURDI的互操作参考设计可移植到**省际低空容量互认与协调** |
| **TRL 8/9→技术就绪度对标** | CISP+USSP+UTM全栈验证至TRL 8/9——为中国低空管理平台（SILAS/榕智九天/杭州平台）的技术成熟度评估提供**国际对标基准** |
| **BVLOS医疗→专用走廊容量** | 30min→<13min（58%时间压缩）——医疗专用BVLOS走廊的**时间-容量-生命价值**三角：$C_{medical}=f(time\_saved, lives\_impacted)$——为容量优先级配置提供**生命价值权重** |
| **社会接受度→多层次$f_{social}$** | BURDI的多层次治理框架→$f_{social}$不应是单一变量，而应分解为$f_{public}+f_{local\_gov}+f_{operators}$——三个子维度独立评估后合成 |
