# 英国Skyway低空高速公路（2022-2024）

> ★ 全球首个大规模**地面传感器驱动**无人机专用高速公路网络。不同于日本AAM走廊的"机载CNS性能驱动"和美国管道范式的"UTM协调"——Skyway开创了第三种走廊范式：通过沿路地面传感器+蜂窝网络实现无人机BVLOS安全运行，265km连接6+2城市，为全球低空基础设施的技术路径选择提供了"英国方案"。

## 核心定位

| 维度 | 定位 |
|:---|:---|
| **全球地位** | ★ 世界最长无人机高速公路（165英里/265km） |
| **技术范式** | **地面传感器驱动**——不同于日本/美国/中国的机载/卫星路径 |
| **治理模式** | 政府基金引导(BEIS/Innovate UK) + 企业技术主导(Altitude Angel/BT) + 监管渐进审查(CAA) |
| **应用层级** | 无人机（BVLOS货运/物流/应急）——**非载人**，与日本eVTOL走廊互补 |

## 一、空域条件

| 维度 | 详情 |
|:---|:---|
| **走廊长度** | **265 km**（165英里） |
| **一期城市** | Reading, Oxford, Milton Keynes, Cambridge, Coventry, Rugby（6城） |
| **延伸目标** | Southampton（南岸）+ Ipswich（东岸） |
| **覆盖区域** | 英国南部及东南部——连接M4/M40/M1走廊经济带 |
| **空域结构** | 专用无人机走廊——在现有有人机空域中划设，ARROW系统确保共存 |
| **运行高度** | 低空空域（具体高度参数待追踪） |
| **运营类型** | ★ BVLOS（超视距）——无人机无需视距内操控 |

## 二、技术方案

### 2.1 ARROW 技术架构

| 层 | 组件 | 功能 | 技术提供方 |
|:---|:---|:---|:---|
| **感知层** | 地面传感器网络（沿公路安装） | 持续监控低空空域→提供无人机实时位置视图 | Altitude Angel（专利） |
| **通信层** | 4G + 5G 蜂窝网络 | 连接传感器↔服务器↔无人机 | BT Group / EE |
| **分析层** | UTM交通管理系统 | 分析传感器数据→生成飞行引导指令 | Altitude Angel |
| **执行层** | 机载DAA（感知与避撞） | 接收ARROW战术防撞指令→执行避撞 | Altitude Angel（2020年开发） |
| **监督层** | 指挥中心 | 初期人工监督→逐步自动化 | 经培训操作员 |

### 2.2 ARROW 技术特征

| 特征 | 说明 | 与机载CNS路径差异 |
|:---|:---|:---|
| **感知外置** | 传感器在地面而非机载→降低无人机成本和重量 | 日本/CNSA路径：昂贵机载设备 |
| **通信公用** | 利用现有4G/5G公网→无需专用航空通信网络 | 传统航空：专用VHF/卫星链路 |
| **避撞集中化** | 地面系统统一计算避撞指令→无人机仅执行 | 日本自主间隔保持：机载自主决策 |
| **覆盖线性** | 沿公路带状部署→覆盖走廊而非全域 | 卫星/雷达：面状覆盖 |
| **扩展弹性** | 增加传感器节点即扩展走廊→线性增长 | 卫星覆盖：固定容量 |

### 2.3 技术合作伙伴生态

| 伙伴 | 角色 | 贡献 |
|:---|:---|:---|
| **Altitude Angel** | ★ 项目牵头方 / UTM提供商 | ARROW专利技术+交通管理系统 |
| **BT Group / EE** | 通信网络提供商 | 英国最大最可靠4G/5G网络连接 |
| **Skyports** | BVLOS运营验证 | 数千小时英国BVLOS飞行经验→试飞验证可行性 |
| **CAA** | 监管审查 | 2023底接收数据→2024.07前安全协议整合 |
| **地方当局** | 地方政府支持 | Reading等城市配合 |
| **Innovate UK (BEIS)** | 政府基金 | 1.055亿英镑综合航空系统专项 |

| 场景 | 说明 | 运营特征 |
|:---|:---|:---|

## 四、动态约束

| 约束类型 | 详情 | 子课题3 映射 |
|:---|:---|:---|
| **传感器覆盖约束** | ARROW地面传感器沿公路线性部署→覆盖仅限走廊带状区域，非走廊区无覆盖 | 地面传感器覆盖范围→走廊容量空间上限——$C_{corridor} \leq f(sensor_{density}, sensor_{range})$ |
| **蜂窝网络依赖** | 依赖4G/5G公网→网络拥塞/基站故障→走廊容量瞬时下降 | 通信可靠性→$f_{CNS}$ 的新维度——不依赖机载设备而依赖地面网络基础设施 |
| **监管渐进瓶颈** | 试飞使用现有许可→CAA审查周期→安全协议整合时间→商业化速度受监管节奏约束 | 渐进式监管→$\frac{dC}{dt}$ 呈阶梯状——每轮审查通过后容量跃升一级 |
| **有人机共存** | Skyway走廊与现有有人机空域重叠→ARROW需同时管理两类飞行器 | 混合空域容量模型——$C_{corridor}=C_{drone}+C_{manned}$，两者互相约束 |
| **线性拓扑约束** | 走廊沿固定路线→偏离路线=失去传感器覆盖→紧急情况备降能力受限 | 线性走廊→节点间无冗余路径→单点故障可致走廊中断（不同于网状拓扑的高鲁棒性） |
| **天气约束** | 英国多雨雾天气→传感器性能下降+无人机飞行包线受限 | 气象折减——不同于GCC高温/沙尘，英国气候约束为降水+低能见度 |

## 五、制度机制

### 5.1 三方协作框架

```
BEIS / Innovate UK ──→ 基金引导（£1.055亿）
       │
       ├──→ Altitude Angel ──→ ARROW技术+UTM
       ├──→ BT / EE ──→ 蜂窝网络连接
       ├──→ Skyports ──→ BVLOS运营验证
       │
       └──→ CAA ──→ 渐进监管审查
              │
              ├── 2023.07：试飞（现有许可）
              ├── 2023底：数据+建议提交
              └── 2024.07：安全协议整合→商业化许可
```

### 5.2 制度特征

| 维度 | 特征 |
|:---|:---|
| **基金模式** | Innovate UK（BEIS下属）——定向基金而非产业基金，聚焦技术验证而非商业孵化 |
| **监管路径** | ★ 渐进式审查——"现有许可试飞→数据提交→安全协议整合→许可升级" |
| **企业角色** | 技术主导——Altitude Angel为核心技术方（非政府研发），BT为商业电信运营商 |
| **应用定位** | 公共服务优先——应急+医疗+邮政→商业物流后置 |
| **国际合作** | CEO明确表态——"出口到全球"——Skyway可复制到其他国家 |

### 5.3 与其他国家治理对比

| 维度 | 英国 | 日本 | 美国 |
|:---|:---|:---|:---|
| **驱动主体** | 企业技术+政府基金 | 政府（国交省/经产省）+大企业 | 企业主导+FAA监管 |
| **走廊技术** | ★ 地面传感器+蜂窝 | 机载CNS+ANSP | UTM+ADS-B |
| **监管模式** | 渐进审查（GBP 4步） | 政企协议会（集中协调） | FAA rulemaking（正式立法） |
| **应用优先级** | 公共服务（应急/医疗/邮政） | 观光→城市交通→全面普及 | 商业物流→城市客运 |

## 六、子课题3 启示

| 维度 | 启示 |
|:---|:---|
| **地面传感器走廊→CNS架构替代** | Skyway提供不同于日本"机载CNS性能驱动"和美国"UTM协调"的第三种走廊范式——地面传感器外置感知+公用蜂窝通信。子课题3的CNS性能折减模型需考虑**传感器位置（机载vs地面vs混合）对容量约束的不同影响**——$f_{CNS}$ 应扩展为 $f_{CNS}(architecture)$ |
| **线性走廊→退化拓扑容量** | Skyway的线性走廊（沿公路）与日本AAM走廊（点对点）和GCC分层走廊（网络化）形成三种拓扑——线性走廊容量模型为**一维流动**：$C_{linear}=v_{uniform}/s_{min}$（最简形式），不存在路径选择冗余 |
| **蜂窝网络可靠性→容量鲁棒性** | Skyway依赖公网→基站故障/网络拥塞→容量瞬时下降——不同于专用航空网络的确定性容量。子课题3需新增 $f_{network\_reliability}$——通信系统可靠性→容量波动方差 |
| **渐进式监管→容量释放阶梯函数** | CAA的"试飞→数据→审查→许可"四步渐进→容量非连续增长——$C(t)$ 呈阶梯状（$C_{phase1} < C_{phase2} < C_{phase3} < C_{phase4}$），每个监管节点→容量跃升 |
| **BVLOS走廊→无人机高密度运行参照** | 265km走廊专用于BVLOS无人机→与日本福岛146次/h（1km²实证）互补——Skyway提供**线性高密度**数据，福岛提供**面状高密度**数据，两者共同构成容量模型标定的多形态数据源 |
| **技术出口→全球走廊范式竞争** | Skyway的"英国方案"（地面传感器+蜂窝）vs 日本方案（机载CNS）vs 美国方案（UTM）——三种走廊技术路线在中国低空基础设施规划中可选择性借鉴或融合 |
