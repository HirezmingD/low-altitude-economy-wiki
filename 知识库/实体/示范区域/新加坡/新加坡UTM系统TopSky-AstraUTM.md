# 新加坡UTM系统：TopSky-AstraUTM（2026-）

> ★ 全球城市密集型治理的**数字化UTM标杆**——2026年5月CAAS授予Thales（泰雷兹）+Deeeplabs联合体合同，部署基于TopSky-AstraUTM的国家级无人机交通管理系统。为新加坡所有UA运行提供**一站式审批与跟踪门户**——运营商/无人机注册+数字飞行计划授权+实时监控——在733km²/570万人口/多个机场终端区重叠的极端约束环境下实现无人机运行的安全可扩展管理。全球-本地联合体模式为低空技术跨国输出提供范本。

## 核心定位

| 维度 | 定位 |
|:---|:---|
| **全球地位** | ★ 全球城市密集型治理模式的首个国家级数字化UTM——极端空域密度下的UTM标杆 |
| **平台** | Thales TopSky-AstraUTM——2024年整合入产品组合，已多国部署 |
| **交付模式** | ★ 全球-本地联合体：Thales（技术+产品·牵头）+ Deeeplabs（部署+运维·本地） |
| **监管机构** | CAAS（新加坡民航局） |
| **核心特征** | ★ 一站式——所有UA运行一个平台一个门户 |

## 一、空域条件

| 维度 | 详情 |
|:---|:---|
| **国土约束** | ★ 733km²——东西~50km/南北~27km——全球最极端的空域密度约束 |
| **人口密度** | ~8,000人/km²——地面风险敞口极大 |
| **机场叠加** | 樟宜国际机场（全球Top 20）+ 实里达机场 + 多个军事机场——终端区高度重叠 |
| **有效低空空域** | 多机场终端区+城市建成区+军事禁区——估计<国土面积50% |
| **跨境约束** | 北邻马来西亚柔佛（1km海峡）+ 南邻印度尼西亚——跨境空域协调需求高 |
| **海事叠加** | 全球最繁忙港口之一+新加坡海峡——海上无人机+城市无人机空域共享 |
| **UTM覆盖** | ★ 全国空域——TopSky-AstraUTM统一管理 |

## 二、技术方案

### 2.1 TopSky-AstraUTM 功能架构

| 功能模块 | 内容 | 制度效率 |
|:---|:---|:---|
| **统一注册** | 运营商+无人机电子身份注册——单一入口 | 消除多部门重复登记 |
| **数字飞行计划与授权** | 在线提交→自动审核→数字授权 | ★ 简化申请流程+缩短监管审批时间 |
| **实时运行监控** | 全空域UA运行态势感知+自动化协调 | 增强安全+提升效率 |
| **全生命周期支持** | 注册→计划→授权→监控→数据存档 | 端到端数字化闭环 |

### 2.2 UTM vs U-space vs SILAS vs ARROW 对标

| 维度 | 新加坡UTM（TopSky-AstraUTM） | 欧盟U-space（BURDI） | 中国SILAS（深圳） | 英国ARROW（Skyway） |
|:---|:---|:---|:---|:---|
| **技术路径** | ★ 国家级UTM平台（商业化产品） | 法规驱动+参考设计实施 | 城市级自研系统 | 地面传感器+蜂窝+集中UTM |
| **覆盖范围** | ★ 全国统一（733km²） | 跨境验证（比利时-荷兰） | 城市级（深圳） | 线性走廊（265km） |
| **服务架构** | Thales AstraUTM（产品） | CISP+USSP+UTM（三层） | 国家-地方两级 | ARROW地面+UTM |
| **核心特征** | ★ 一站式门户+商业产品标准化 | 法规标准化→全欧推广 | 全链条闭环管理 | 地面感知外置 |
| **部署模式** | ★ 全球技术+本地伙伴联合体 | 欧盟基金+多国联盟 | 政府自建 | 企业主导+政府协调 |

## 四、动态约束

| 约束类型 | 详情 | 子课题3 映射 |
|:---|:---|:---|

| **人口极密** | 8,000人/km²→任何UA坠落→地面人员伤亡风险极高 | $f_{risk}$→$s_{min}$最大化→$C_{effective}$最小化——安全约束对容量的极端压制 |

## 五、制度机制

### 5.1 治理架构：数字化一站式

```
CAAS（新加坡民航局）
      │ 监管+空域管理+制度保障
      │
      ▼
TopSky-AstraUTM（★ 国家级UTM统一平台）
      │ 统一注册+数字授权+实时监控
      │
      ├──→ 物流无人机
      ├──→ 基础设施巡检
      ├──→ 海事作业
      ├──→ 应急响应
      └──→ 城市交通
```

### 5.2 治理特征

| 维度 | 内容 |
|:---|:---|
| **平台模式** | ★ 全国统一、单一平台、一站式门户——不同于中国的"国家-地方双级"（SILAS）、欧盟的"多国参考设计→各自实施"（BURDI） |
| **交付模式** | 商业产品采购+本地合作伙伴——不同于自研（中国SILAS）、基金资助研发（欧盟BURDI） |
| **监管效率** | 统一平台→简化申请+缩短审批时间+增强态势感知——"数字化一站式"的极致效率 |
| **战略嵌入** | 新加坡"智慧国家"（Smart Nation）战略——UTM是国家数字化转型的组成部分 |

### 5.3 小国UTM模式：全国统一+商业产品

> ★ 新加坡模式的核心启示：对于国土面积小、空域约束极端的城市国家/城市，**全国统一UTM平台+成熟商业产品采购+本地伙伴部署**是最优路径——无需自研的冗长周期，无需多平台协调的制度摩擦。"小而统一"的制度优势可转化为UTM部署的极致效率。

## 六、子课题3 启示

| 维度 | 启示 |
|:---|:---|
| **极端密度→容量模型边界值** | 733km²/有效低空<366km²→$C_{max}/km²$为全球最高可能值——为容量密度上限研究提供**理论边界值标定** |
| **一站式vs双级→制度效率→容量释放** | 新加坡全国统一平台→零跨区域协调摩擦→$\frac{dC}{dt}$最大化——与中国的"国家-省-市"三级制度摩擦形成对照→制度复杂度与容量释放速率成反比 |
| **商业产品vs自研→部署速度** | Thales AstraUTM为成熟产品→部署周期远短于自研——技术成熟度→$\Delta t_{deploy}$——直接决定$C(t)$的增长起点 |
| **多机场终端区→极限混合容量** | 樟宜+实里达+军航在733km²内重叠→$C_{UAS}+C_{ATM}$在极小空间的极限共存——为混合空域容量模型提供**最极端约束参数集** |
| **跨境1km→制度边界最短距离** | 柔佛海峡仅1km→地理围栏精度需<1km→制度边界衰减$\eta_{border}$取最大值——跨境容量协调的**最短距离案例** |
