# DigitalSky 中央监管与数据交换平台（印度）

> **DigitalSky**——印度DGCA（民航总局）的中央监管与数据交换平台。全球UTM治理**第四种范式**（多供应商分布式）的核心枢纽——DGCA通过DigitalSky管理全国无人机运行，多个公私UTM服务提供商通过共同互操作标准持续同步。Very Low Level空域（地面至1000ft AGL）定义为UTM空域。分阶段实施——试验→整合→渐进规模化。

## 基本属性

| 属性 | 内容 |
|:---|:---|
| **名称** | DigitalSky |
| **监管机构** | DGCA（印度民航总局） |
| **架构模式** | ★中央监管与数据交换平台 + 多UTM服务提供商 |
| **UTM空域** | Very Low Level——地面至**1000ft** AGL |
| **协调机制** | 共同互操作标准——不同供应商持续同步 |
| **实施路径** | ★分阶段——试验→整合演练→渐进式规模化运营 |
| **治理范式** | ★全球第四种UTM范式——多供应商分布式 |

## 核心功能

| 功能 | 描述 |
|:---|:---|
| **统一注册** | 全国无人机+运营商统一注册 |
| **许可管理** | 飞行许可的申请/审批/追踪 |
| **空域信息发布** | 实时空域状态信息→所有供应商同步 |
| **利益相关方整合** | 运营商+供应商+监管方→统一数据交换 |
| **互操作协调** | 多供应商间通过共同标准持续同步 |

## 系统架构

```
              DigitalSky 系统架构
                      │
              DGCA（中央监管）
                      │
              DigitalSky 平台
              （注册+许可+空域信息+数据交换）
                      │
        ┌─────────────┼─────────────┐
        │             │             │
    UTM供应商A    UTM供应商B    UTM供应商C
    （公私混合）    （公私混合）    （公私混合）
        │             │             │
    互操作标准 ←──→ 互操作标准 ←──→ 互操作标准
```

## 核心挑战

| 挑战 | 详情 | 子课题3映射 |
|:---|:---|:---|
| **交通可见性** | 多供应商各自管理→全局态势碎片化 | ★$f_{coordination}$ |
| **跨供应商移交** | UA跨区域→移交协议+责任划分 | 跨区容量损失 |
| **临时限制同步** | 实时同步至所有供应商 | 同步延迟→容量波动 |
| **航线冲突** | 共享走廊→多供应商航线交叉 | 冲突消解→容量折减 |
| **地理围栏一致性** | 所有供应商同步更新 | 不一致→安全风险 |
| **1000ft垂直界面** | UTM↔ATM垂直协调 | 界面容量耦合 |

## 与子课题3关联

| 维度 | 关联 |
|:---|:---|
| **多供应商→容量折减** | $C_{multi}=C_{single}\times\eta_{coordination}(n_{providers})$——$\eta_{coordination}$随供应商数量增加而递减 |
| **互操作标准→η大小** | 标准化程度越高→协调摩擦越小→容量折减越小 |
| **分阶段→容量阶梯** | $C(t)$呈阶梯状——每阶段验证通过后容量跃升 |
| **1000ft界面→垂直耦合** | UTM-ATM垂直边界→容量交互约束模型 |

## 四系统UTM治理范式对标

| 范式 | 系统 | 架构 | 协调方式 |
|:---|:---|:---|:---|
| ★ **分布式** | DigitalSky | 中央平台+多供应商 | 互操作标准同步 |
| **统一式** | TopSky-AstraUTM（新加坡） | 全国单一平台 | 平台内部统一 |
| **一体式** | Avinor UTM（挪威） | ANSP全国系统 | U-space法规统一 |
| **法规式** | BURDI参考设计（欧盟） | CISP+USSP+UTM | EU法规→各国实施 |
