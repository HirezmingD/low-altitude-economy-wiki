# 时空数据管理引擎

## 定义

**时空数据管理引擎**是支撑城市低空适飞空域网格化剖分管理的核心数据架构，负责整合地形地貌、气象条件、空域资源、飞行活动等多源时空数据，为低空空域的精细分配与动态管理提供数据底座。由董志毅（2025）明确提出，定位为低空新治理体系的**数据基础设施核心**。

## 在低空治理体系中的定位

```
┌───────────────────────────────────────┐
│         低空安全新治理体系              │
├───────────────────────────────────────┤
│  网格化剖分管理  ←──支撑──→  数字飞行规则 │
│         │                      │       │
│         └──────────┬───────────┘       │
│                    ↓                   │
│         时空数据管理引擎                │
│         (数据底座)                      │
│                    ↓                   │
│    精细分配与动态管理能力               │
└───────────────────────────────────────┘
```

## 数据架构

| 数据层 | 内容 | 时空粒度 | 更新频率 |
|:---|:---|:---|:---|
| **静态地理层** | 地形DEM、建筑物模型、禁飞区边界 | 米级网格 | 按需更新 |
| **动态气象层** | 风速风向、能见度、降水、微气象 | 百米级网格 | 分钟级 |
| **空域结构层** | 空域分类边界、航路网络、网格编码 | 网格级 | 按需更新 |
| **实时飞行层** | 飞行器位置、速度、航向、飞行计划 | 飞行器级 | 秒级 |
| **设施状态层** | 起降点容量、通信导航设备状态 | 站点级 | 分钟级 |

## 核心功能

### 1. 时空索引

- 基于三维网格编码（地理网格 + 高度层 + 时间片）的统一时空索引
- 网格编码标准：**《北斗网格位置码》（GB）** + GeoSOT 地球立体网格编码理论（程承旗，北大）
- 支持按空间范围（10m/20m 粒度）、高度区间、时间窗口的多维快速查询

### 2. 数据融合

- 多源异构数据的时空对齐与融合
- 消除不同系统（气象/空管/通信）间的数据不一致

### 3. 动态更新

- 实时数据流的增量更新
- 历史数据的版本管理与回溯

### 4. 服务接口

- 为上层应用（容量评估、态势预测、调度决策）提供统一数据服务

## 与子课题3 的关系

时空数据管理引擎是子课题3 三大技术模块的**共同数据基座**：

| 子课题3 技术 | 对时空引擎的数据需求 |
|:---|:---|
| 多因素耦合容量评估 | 静态地理 + 动态气象 + 空域结构的融合数据 |
| ST-GNN 态势预测 | 实时飞行层的时空序列数据 |
| 饱和度监测预警 | 所有数据层的综合实时推送 |

## 技术挑战

- 多源数据的时间同步精度
- 大规模实时数据流的低延迟处理
- 三维网格编码与现有空域分类体系的映射
- 数据安全与访问控制（与内生安全协同）
